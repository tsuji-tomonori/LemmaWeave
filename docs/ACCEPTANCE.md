# 受入条件・監査テスト仕様

以下は実装時に用意する判定とテストであり、本パッケージで実行済みのCIではない。

## 1. 小問のPhase 1完了

| ID | 必須判定 | 保存する証拠 |
|---|---|---|
| AC01 | 原資料・出題位置・版が特定され、対象行為の権利条件を確認している | source/paper record、取得記録、条件 |
| AC02 | 原ページの数式・図表と転記・数学的仕様が一致する | ページを直接確認したレビュー |
| AC03 | 原問題に求められた全結論が命題に含まれる | 要求→Lean定理の対応表 |
| AC04 | 命題・仮定・定義域を独立レビューした | 独立セッションID、型と仕様のハッシュ |
| AC05 | 固定環境で対象定理と依存が実際にビルド成功した | コマンド、終了コード0、ログ、commit |
| AC06 | 推移的な公理依存が許容リスト内である | 定理ごとの公理監査出力 |
| AC07 | 隠れた仮定・循環的な答えの仮定・不適切なモデル化がない | 意味レビュー、充足可能性の点検 |
| AC08 | 型・証明項からの実依存を抽出し、未取得箇所を隠していない | 生依存グラフ、抽出器版、境界一覧 |
| AC09 | 数学的依存が小中前提・補題・基礎付録へ写像されている | 補題カード、分類根拠、未分類0 |
| AC10 | 学習順の辺に循環がなく、別解と関連辺を分離した | グラフ検査結果 |
| AC11 | 必要な日本語の主張と説明骨子、未展開箇所を保存した | learning_nodes、educational_frontier |
| AC12 | 同じ入力・固定環境で再実行可能である | 別環境の実行記録、依存lock |

AC09の「未分類0」は、あらゆるmathlib宣言を教科書の章にするという意味ではない。内部実装は明示的な監査済み分類にまとめられる。一方、数学的な定理を「その他」として隠すことは不可。

AC11は教科書全文・全基礎定理の初等的説明の完成を意味しない。未展開の数学的前提は個別に残せばよい。

原資料再配布の許可は、証明監査の完了と独立した公開ゲートとする。公開未許諾でも、実施した内部処理が許される範囲での証明記録は保持できる。

## 2. 必ず落とすべきテスト

### 証明と台帳

- 登録した合格宣言に直接 `sorry` がある → 不合格。
- 別ファイルの定理を経由して `sorryAx` へ依存する → 不合格。
- タクティクが生成した未許可公理、独自 `axiom` に依存する → 不合格。
- 警告や失敗を握りつぶし終了コードだけを0にする → 不合格。
- 台帳にある定理ファイルを集約対象から削除して成功させる → 不合格。
- 前回成功ログを別のproof hash／commitに流用する → 不合格。
- Pythonの有限全探索だけが通る → `proof_status` を昇格させない。

### 意味の対応

- 原題の「実数」を自然数に変えて有限検査する → 意味レビューで不合格。
- 全解を求める問題で、一つの解の代入確認だけを証明する → 不合格。
- 最小値の問題で下界だけ証明し、達成しない → 不合格。
- 無根拠な座標・直角・等長を図から仮定に追加する → 不合格。
- 型の仮定として `False` や答えそのものを渡す → Leanが通っても不合格。
- 有限モデルを検査したが原モデルとの同値性がない → 不合格。
- 近似値を厳密な等式へ変える → 不合格。
- 検証済み後に原題の訂正やモデルの定義変更がある → `stale`。

充足可能性の点検は重要だが、それだけで原題への忠実さを自動判定できるとはしない。上のケースは仕様レビューの回帰テストも含む。

### 補題抽出

- `simp` が使った事実を、ソースに名前がないため落とす → 不合格。
- ラッパー定理だけを記録し、その裏の数学的依存を省く → 不合格。
- 公理一覧だけを補題一覧として出す → 不合格。
- 依存走査が上限に到達したのに「完全」と表示する → 不合格。
- 高校を超える定理をすべて実装詳細として除外する → 不合格。
- 実数の完備性を「実数は中学で習った」で既習扱いする → 不合格。
- 同一の数学内容を多数の別名で登録して補題数を増やす → 不合格。
- 本来は別解で選べる依存を全部必須として合併する → 修正要求。
- 生グラフの再帰を学習順の循環と誤認する → 修正要求。

### 権利と集計

- 公開閲覧できる原題を再配布可に自動昇格する → 不合格。
- 未許可の本文・画像をCI成果物やエージェント外部送信へ流す → 不合格。
- 同一冊子のミラーを異なる問題群として二重計上する → 不合格。
- 7解答欄を、数学的に3小問しかないのに7問と数える → 不合格。
- 存在確認していない年度を「収集済み」と表示する → 不合格。

## 3. 抽出器のテストデータ

本番問題ではなく、独自の小さな検査用定理を用意する。これは入試問題数に入れない。

明示的なlemma呼出し、`simp`による暗黙利用、型にのみ現れる定義、型クラスを介した依存、ラッパー、共有補題、相互定義、公理違反、取得不能な証明本体を用意する。それぞれ期待される参照の存在と境界記録を検査する。

期待値を全宣言名の完全固定リストにするとLean版変更の細部に過剰依存するため、最低限必須の辺・禁止公理・完全性状態を中心に比較し、版変更時は差分をレビューする。

## 4. パイロットの受入

目標は原資料確認済み50小問・6分野、Phase 1完了10小問・4分野。最低1件は図形または近似・データ等のモデル化の難しさを扱い、有限列挙だけではない証明を含める。到達できなければ目標値を書き換えず、実績と不足理由を明示する。

コード・台帳・レビューがバラバラに更新されず、ある問題から使用補題、補題から利用問題へ相互に追跡できること。教材全文がなくても、補題の名称だけでなく主張と前提が読めること。
