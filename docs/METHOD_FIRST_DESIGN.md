# 解法・概念を中心とする知識基盤（ユーザー訂正、2026-09-05）

この文書は今回のユーザー指示を具体化し、以前の「少数の入試問題の答えをLeanで確認する」進め方を変更する。旧13問・50問パイロットは試運転の履歴であり、最終対象範囲ではない。

## 成果物

中心となる成果物は、公式・定義・概念・解法技法の再利用可能なライブラリと、それらの組合せで解法を再構成できる根拠グラフ。Leanは各公式と変形の正当性、条件の保存、結論への接続を検査する。数値や真偽の出力だけでは解法完成としない。

問題 → 解法バリアント → 根拠付きステップ → 公式／方法 → 前提概念・補題という参照を両方向に辿れるようにする。例：二次関数の極値 → 平方完成 → 平方の非負性と係数の符号 → 頂点の位置 → 達成確認。端点での最大値には区間と頂点位置の条件も必要。

概念は定義、公式は条件付き定理、解法技法は適用条件と変換前後の関係として持つ。定義を無理に「証明すべき定理」と呼ばない。図形の補助線や座標化、置換、場合分け、対称性、帰納法なども方法ノードにする。

## 学習ノードとレシピ

`knowledge/method_nodes/` は新しい方法・概念ノード、`knowledge/recipes/` は問題に適用するステップの正本JSON。既存の `knowledge/nodes/`（カーネル依存の分類カード）とは役割を分ける。新ノードには正確な日本語の主張、仮定、使う場面、適用できない条件、Lean宣言、前提、説明骨子、未展開部分を保持する。

レシピには順序、前提ステップ、適用する補題、適用で満たすべき条件、得られる主張、Lean上の対応宣言を明示する。生成Markdownは問題からノードへ、ノードから使用レシピへリンクする。リンクが存在するだけでは根拠検証済みにしない。まず実例の依存グラフ上に根拠宣言が存在することを検査する。各自然言語ステップの完全な意味照合は別のレビュー状態にする。

## 大量収集・共通化

1. 公式入試・利用可能な問題集・公開データセットを出典と許諾単位で登録。日本入試、海外競技、一般問題、合成問題を別コレクションにする。
2. 原資料単位の取得ハッシュ、レコード数、問題内容の重複、複数解答を分離して数える。100万の解答文を100万の異なる問題とは呼ばない。
3. 数学Ⅰ・Ⅱ・Ⅲ・A・B・Cの版付き内容区分へ対応付ける。問題数と分野網羅率を別指標にする。小中の前提台帳も別管理。
4. 解法をステップに分け、既存の公式・方法を検索して再利用。足りない概念だけ追加する。命題の名前や表層類似だけで同値扱いしない。
5. 原題と仕様の照合後、ステップの補題適用をLeanで検証。未形式化・失敗・時間切れも保持し、成功だけを残さない。
6. 同じ方法を使う問題群から、仮定を保持した一般的補題へ共通化する。一般化の正しさは別途証明し、元の解法への特殊化を示す。

規模目標は10,000独立問題での収集・重複整理・解法抽出を第一拡大量、100,000以上を次段階とする。目標件数と取得済み・形式化済み・検証済みの件数を明確に分離し、段階ごとに分野の偏りと未利用技法を再評価する。全国・全問題集の分母が未確定な「全問題完了」は表示しない。

## 分解の停止境界と完了判定

数学的な前提を隠さず分解するが、Leanのパーサやメモリ配置などの内部実装は学習手順へ混ぜない。形式依存の完全監査は保持し、学習上の前提と別表示する。小中で説明を省く範囲は文科省の版付き根拠で判断し、実数の完備性などは必要な基礎付録として残す。

今回の方法レシピ実例だけでは、新しい大規模方針の完成ではない。大量コーパス全体の解法抽出、すべての方法の再利用・同値性判定、全分野説明、学習UIは未完成として報告する。1問を別解で解き直しても新規問題数を増やさない。
