# LemmaWeave — レマウィーブ

**入試問題をほどき、補題で数学を編み直す。**

- リポジトリ名：`lemmaweave`
- Lean 4 名前空間：`LemmaWeave`
- 第1段階：公開入試数学の収集・形式化・証明・補題の抽出と分類
- 将来：小中学校の既習事項から高校数学を依存順に学び直す教材
- 文書版：0.1 / 2026-09-05

このパッケージは**要件・実行プロンプト・データ記録様式**です。問題コーパス、Lean実装、検証済みの定理、実装済みのCIを新たに作成したものではありません。各件数は今後のマイルストーン目標です。

## 使い始める

作業対象のリポジトリに、このパッケージを配置する。既存の `AGENTS.md` がある場合は上書きせず、ルールの差分を統合する。

最初に `REQUIREMENTS.md` と `docs/ACCEPTANCE.md` を確認し、開発エージェントに `PROMPT_START.md` を渡す。長い実行を一度に要求せず、最初の5小問のバッチで、少なくとも1小問の収集から監査・補題抽出までを実際につなぐ。その結果を踏まえ、50小問の収集・10小問の証明監査完了へ拡張する。

継続時は `prompts/07-resume.md`、役割を分ける場合は `prompts/` の各ファイルを使用する。独立レビューは、別エージェントまたは作成時の推論を引き継がない別セッションで行い、同じエージェントによる再確認を独立レビューと表示しない。

## ファイル

| ファイル | 役割 |
|---|---|
| `REQUIREMENTS.md` | 目的、対象、収集・形式化・検証・補題抽出の必須要件 |
| `PROMPT_START.md` | 最初に渡す統括実行プロンプト |
| `PROMPTS.md` | 全プロンプトをまとめて読む版 |
| `AGENTS.md` | 作業エージェントが毎回守る実装・検証・報告ルール |
| `docs/DATA_CONTRACT.md` | データ単位、必須項目、状態、依存関係、集計規約 |
| `docs/ACCEPTANCE.md` | 完成判定と、不正な成功を防ぐテストの仕様 |
| `docs/ROADMAP.md` | 初回・パイロット・収集拡大の段階 |
| `docs/MIGRATION.md` | 既存の試作成果物を未検証の種データとして移行する方法 |
| `docs/REFERENCES.md` | 設計の根拠にした一次資料 |
| `templates/` | 問題、補題、出典、実行、レビュー、バッチのYAML記録例 |

## 最重要の区別

`収集済み ≠ 命題確認済み ≠ Lean検証済み ≠ 補題棚卸し済み ≠ 教材完成`

Phase 1では、上の前四者を別々の証拠で管理する。教科書全文・全補題の初等的な説明の完成は要求しない。ただし、未説明の数学的前提を隠さず、補題・基礎付録の台帳と未展開箇所に残す。

名前は本プロジェクト用の採用案であり、商標・ドメイン・全サービス上の名称の利用可能性を保証するものではない。
